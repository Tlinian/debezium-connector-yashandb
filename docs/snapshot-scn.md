# 指定全量快照和增量起始 SCN

在连接器配置中添加 `snapshot.scn`，即可指定全量快照的 SCN，并从该 SCN 加 1 开始后续增量读取：

```json
{
  "snapshot.mode": "initial",
  "snapshot.scn": "123456"
}
```

连接器对捕获的每张表执行 `AS OF SCN 123456` 全量查询，并将 YStream 的恢复起点设为 `123457`。
从下一个 SCN 开始读取增量，避免重放已包含在全量快照中的变更。

`snapshot.scn` 是可选配置，取值范围为 `1` 到 `9223372036854775807` 的整数。
零、负数、空字符串、非整数和超出范围的值会在配置校验时被拒绝。
未配置时，连接器继续自动获取快照 SCN，并从该 SCN 加 1 开始增量读取。

## 已有位点和重启

该配置在启动快照需要确定新位点时生效，并遵循 `snapshot.mode` 的快照策略：

- `initial`：没有完成过快照时，使用指定 SCN 执行全量，随后从该 SCN 加 1 开始读取增量。
- `initial_only`：使用指定 SCN 执行全量，完成后停止。
- `always`：每次启动都重新执行快照，使用配置的 SCN 确定新的全量和增量起点。
- 已完成快照后的正常恢复：使用持久化的增量位点继续读取，修改 `snapshot.scn` 不会自动回退进度。
- 模式历史恢复和按信号触发的阻塞快照：继续使用既有位点逻辑。

需要在已有任务上重新从指定 SCN 做全量和增量时，应使用独立的连接器位点与模式历史。

## 数据库条件和边界

数据库需要保留指定 SCN 对应的闪回数据，以及从下一个 SCN 开始的 YStream 日志，YStream 服务也需要能够从该增量起点恢复。
捕获表的结构需要与该时间点的数据兼容；连接器不会恢复历史表结构。

配置了自定义快照 SELECT 时，应通过 `snapshot.enhance.predicate.scn` 的占位符替换插入相同的
`AS OF SCN` 子句，或在 SELECT 中明确指定相同的 SCN。

原生模式和通过 `ystream.additional.properties.mysql.mode=true` 选择的 MySQL 兼容模式均使用此配置。
